# 0.2.3 릴리스

## 범위

Paseo 서비스 관리·연결 검사와 모바일 서비스 이름 잘림 수정을 하나의 패치 릴리스로 게시한다.
버전은 pyproject, Python 패키지, uv 잠금을 0.2.3으로 맞춘다.
앞서 운영에 적용한 기능 및 CSS 커밋과 GitHub 릴리스·운영 버전 갱신을 구분해서 기록한다.

## 변경

- Paseo 유닛 예제, 등록 정보, HTTP·로컬·릴레이 검사와 상태 UI.
- 모바일 이름 영역이 0px로 축소되는 카드 레이아웃 수정, PC 상태 배지 줄바꿈.
- 서비스명 텍스트 경계·셀 내부 넘침에 대한 PC/모바일 회귀 검사.
- 격리 Paseo 서비스 수명주기 검사를 릴리스 공통 CI에 연결. 새 사용자 홈에서도 실행할 수 있도록 테스트 유닛 디렉터리를 준비한다.
- CHANGELOG와 배포 압축본 예제 버전 갱신. 첫 PR CI의 개발 의존성 감사에서 certifi 2026.7.22의 `PYSEC-2026-4320`이 발견돼 해당 패키지만 2026.10.19로 갱신했다. 웹 런타임 의존성 감사는 통과했다.

## 운영 적용과 복사본 정리

2026-10-22 21:14 KST에 운영 웹·컨트롤러·CLI·시스템 Guard를 0.2.3으로 갱신했다.
root/owner BUILD는 모두 `0085f9dcf71b`·dirty=false이고 `wrg --version`은 0.2.3이다.
Paseo의 PID·InvocationID와 기존 설정 해시는 배포 전후 동일하며 NRestarts=0이다.
WRG에 등록된 Paseo는 자동 시작이 켜져 있고 HTTP·로컬·릴레이 모두 정상이다(검증 당시 290ms/430ms).
실제 운영 웹은 레이아웃 정착 후 390px/1440px에서 LLM Usage와 Paseo 이름·상태 셀의 표시 너비와 잘림을 재확인했다.

최초 운영 버전 갱신은 별도 배포 래퍼가 압축본을 root 전용 디렉터리에 풀어 사용자 권한 설치 단계의 모듈 읽기가 실패했다.
설치기가 기존 운영본으로 복구했으며 Paseo는 중단되지 않았다. 이 오류는 릴리스 코드 수정 없이 배포 래퍼를 고쳐 해결했다.
검증된 릴리스 커밋과 일치하는 기존 개발 체크아웃을 사용해 다시 설치했으며 별도 소스 복사본을 만들지 않았다.

사용자 요청에 따라 이번 작업의 임시 압축본·검사 로그·실패한 설치 소스·전환용 유닛 복사본·배포 스크립트 디렉터리·미사용 실패 가상환경을 삭제했다.
운영에 필요한 설치본과 실행 환경, 설치기에서 만든 복구 백업, 배포 결과/로그만 보존한다.
개발 체크아웃은 기존 프로젝트 하나이며 작업 브랜치와 임시 테스트 유닛도 정리한다.
Windows/WSL 실제 재부팅 및 모바일 단말 자체의 연결 시험은 수행하지 않았다. WSL 시작 시 systemd 자동 실행은 enabled로 확인했다.
