# 개발 프로젝트 경로 통합

## 이유와 변경

공개 준비 때 비공개 Git 이력 유입을 막으려고 별도 공개 체크아웃을 만들었다.
공개 이후에도 두 개발 폴더를 남긴 것은 불필요했다. 개발 경로를 원래 이름인
`~/projects/wsl-resource-guard` 하나로 통합했다.

- 기존 디렉터리 자체와 `.venv`를 유지해 열린 세션의 작업 경로와 가상환경 절대 경로를 보존했다.
- 최신 공개 코드와 `.git`을 기존 경로로 옮겼다. 비공개 이력을 공개 이력에 병합하지 않았다.
- 과거 비공개 코드·Git 이력·개인 산출물은 projects 밖의 비공개 보관 위치로 이동했다.
- `wsl-resource-guard-public` 디렉터리는 비운 뒤 제거했다.
- 설치된 서비스 코드·환경·설정과 기존 로컬 bare 보관 저장소는 변경하지 않았다.

## 검증

- 이동 전 두 체크아웃의 tracked 변경이 없고 추가 worktree가 없음을 확인했다.
- 새 기본 경로의 HEAD는 이동 직후 기존 공개 main과 같은 `2a94ba3`이며 origin도 공개 GitHub다.
- 운영 서비스 실행 경로는 개발 체크아웃 밖에 있다. 서비스 세 개의 PID와 시작 시각을 보존했고
  웹 healthz 응답도 정상이다. 서비스 재시작·운영 배포는 하지 않았다.
- 경로 통합 규칙과 기록만 변경했으므로 공개정보·문서 링크·Git diff 및 CLI 실행을 확인한다.
  제품 코드 변경이 없어 전체 단위·브라우저 검사는 반복하지 않는다.
