# 최신 코드 운영 배포

## 적용

- 배포 기준은 공개 main의 `8130fa9`이다. 기존 개발 경로와 운영 설치 구조를 유지했다.
- `install-services.sh` 다음 `install-root.sh` 순서로 웹·컨트롤러·시스템 guard를 갱신했다.
- uv 0.12.23으로 최종 경로의 새 웹 환경을 만들고 잠금 의존성 8개의 해시·호환성을 확인했다.
  운영 Gunicorn은 26.2.0이다. 웹과 사용자 설치본의 BUILD 커밋은 모두 배포 기준과 같고 dirty=false다.
- 웹·컨트롤러는 2026-10-08 07:26 KST, 시스템 guard는 07:26 KST에 새 프로세스로 전환됐다.
  다른 앱이나 WSL 전체를 재시작하지 않았다.

## 실제 운영 검증

- 세 유닛 active, loopback healthz 정상, doctor의 설치 커밋 일치와 웹·컨트롤러·시스템 guard 정상.
- 사용자 guard의 inactive 표시는 시스템 guard를 사용하는 현재 구성에 해당한다.
- 실제 Tailscale HTTPS 주소에서 기존 browser_smoke 검사를 실행해 PC·모바일의 모든 화면,
  필터, 자동·수동 갱신, 숨김 탭 중지와 중복 요청 방지를 확인했다. fixture 서버가 아닌 운영 서버 검사다.
- 서비스 등록 정보와 웹 접근 설정의 배포 전후 해시가 동일하다.
- 무관한 실행 서비스의 PID 및 Docker 컨테이너 실행 목록이 동일하다.
- 배포 이후 세 유닛의 error 등급 로그는 없다.

## 정리

- 성공 검증 후 이번 설치가 생성한 root 복구 기록 2개와 사용자 복구 기록 2개를 삭제했다.
- 어떤 프로세스도 사용하지 않음을 확인한 이전 웹 `.venv`를 삭제했다. 새 운영 환경은 유지한다.
- 브라우저 스크린샷, 임시 검증 정보와 임시 디렉터리를 삭제했다.
- 사용자 설정·비밀값·상태·이력, 개발 가상환경과 현재 운영에 필요한 설치 파일은 보존했다.
- 이 기록은 배포 후 문서 변경이며 제품 코드 변경은 없다. 기록 커밋을 위해 운영을 다시 시작하지 않는다.
