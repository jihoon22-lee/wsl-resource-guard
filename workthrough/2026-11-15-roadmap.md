# 2026-11-15 작업 로드맵 — 리뷰 후속과 Windows 확장

[상세 코드 리뷰와 Windows 확장 검토](2026-11-15-windows-wsl-expansion-review.md)의 N1–N7, S1–S5, Windows 확장 1–4단계, 구현 언어 검토를 실행 순서로 묶은 계획이다. 이 문서는 계획이며 구현·검증 결과가 아니다.

## 진행 원칙

- 마일스톤 하나가 작업 브랜치 하나, 작업 기록(`workthrough/YYYY-MM-DD-scope.md`) 하나, 릴리스 후보 하나다. 각 마일스톤은 단독으로 동작하고 검증할 수 있어야 한다.
- 상세 구현 계획은 마일스톤을 시작할 때 쓴다. 뒤 마일스톤의 인터페이스는 앞 마일스톤의 결과에 따라 달라지기 때문이다. 지금 상세 계획이 있는 것은 M1뿐이다: [M1 구현 계획](2026-11-15-plan-m1-alert-reliability.md).
- 결함 수정은 실패하는 회귀 검사를 먼저 고정한다. 로직 변경은 단위 검사 전체, 화면 변경은 브라우저 검사를 실행한다([AGENTS.md](../AGENTS.md)의 검증 기준).
- 릴리스 태그·원격 push·운영 배포는 마일스톤 완료와 별개이며 요청이 있을 때 한다.
- 미관측을 0·정상으로 채우지 않는다. Windows 측에서는 조회만 하고, 웹 요청이 임의 명령·경로를 실행하지 않는 경계를 유지한다.

M6은 M2 뒤라면 다른 마일스톤과 병행할 수 있다. 나머지는 표의 순서대로 진행한다.

### M1 — 알림 신뢰성

- **목표:** 지속 중인 디스크 경보가 WSL 재시작으로 다시 열리거나 거짓 회복을 알리지 않는다. Windows 토스트 경로가 멈춰도 다른 채널은 계속 전송한다. 전송 실패의 원인이 기록과 저널에 남는다.
- **범위:** `incidents.py`의 사건 키와 저장소 이전, `notifications.py`의 토스트 시간 제한, `delivery.py`의 실패 원인 보관, 사건 상세 화면의 원인 표시 한 줄.
- **완료 기준:** 리뷰에서 재현한 두 시나리오가 회귀 검사로 고정되고 통과한다. 단위 검사 전체, JS 구문 검사, `browser_actionable.py`가 통과한다.
- **범위 밖:** 호스트 연결 모듈로의 통합(M3), 정기 이메일 실패 원인 보관.

### M2 — 기반 정리

- **목표:** 뒤 마일스톤이 새 저장 파일과 새 수집 경로를 추가하기 전에 공통 기반을 하나로 만든다.
- **범위:**
  - 원자적 저장 구현 5곳과 `webpush.send_all`의 비원자적 저장을 한 모듈로 모은다(S3).
  - Guard 유닛을 `Type=notify`와 `WatchdogSec`으로 바꾸고 표본 완료마다 생존 신호를 보낸다(N6의 Linux 측).
  - 주간 리포트가 같은 ISO 주 안에서 놓친 발송을 따라잡게 한다(N7).
  - `state.json`·`incidents.json`·`delivery.json`·컨트롤러 소켓 요청의 형식을 `docs/`에 문서화하고 버전 필드 규칙을 정한다. M3의 `metrics.host`와 M8의 구성요소 교체가 이 문서를 기준으로 한다.
- **완료 기준:** 저장 경로별 회귀 검사, 표본 루프 정지 시 유닛 재시작을 격리된 유닛으로 확인, 형식 문서가 실제 파일과 일치하는지 검사.
- **확인할 것:** watchdog 시간은 가장 긴 정상 표본(OOM 조회 10초, 드라이브 조회 제한 5초 포함)보다 충분히 길어야 한다.

### M3 — 호스트 관측 (Windows 확장 1단계)

- **목표:** 설치 없이 WSL 안에서 Windows 호스트 상태를 읽어 화면에 보여 준다. 경보에는 아직 연결하지 않는다.
- **범위:**
  - Windows 호출을 전담하는 모듈 하나: 실행 파일 위치 확인, 시간 제한, 단일 실행, 연속 실패 시 간격 확대, 출력 크기 제한, 고정 스크립트만 실행. M1에서 따로 감싼 토스트와 현재의 vmmem 조회, doctor의 `.wslconfig` 탐색을 여기로 옮긴다(S5).
  - 호스트 스냅샷: 물리 메모리 전체·여유, 커밋 사용량·한도, 페이지 파일, vmmem, 고정 볼륨 전체, 배포판 목록·상태, VHDX 위치 자동 탐지, `.wslconfig` 유효 한도.
  - 저장은 `metrics.host` 아래의 버전 있는 구조와 낮은 주기의 별도 이력 파일. 관측 시각·시도 시각·상태를 함께 둔다.
  - 화면: 호스트 메모리, vmmem 대비 WSL 내부 사용량, 배포판 상태, 고정 볼륨. CLI `wrg status`·`wrg doctor`에도 반영한다.
- **완료 기준:** 각 조회의 정지·실패·형식 오류 주입 검사, interop이 없는 환경에서 "미제공"으로 표시, 브라우저 PC·모바일 검사, 실제 호스트에서 수신 확인(fixture 통과와 구분해 기록).
- **결정 필요:** D1, D2.

### M4 — 판정 구조 정리

- **목표:** `daemon.sample()`을 수집·평가·유지 판정·저장으로 나누고, 회복 판정을 한 곳으로 모은다. M5에서 호스트 조건을 추가할 때 PSI·디스크에 이은 세 번째 개별 유지 분기를 만들지 않기 위해서다.
- **범위:** 미관측 시 경보 유지 규칙을 조건 종류별 공통 규칙으로 정리하고, 데몬이 쓰지 않는 구형 알림 경로(`notify=True`)를 분리하거나 제거한다. 동작 변경은 없다.
- **완료 기준:** 기존 단위 검사 전체가 수정 없이 통과한다(구형 경로 제거를 택하면 그 검사만 함께 정리). 실제 표본 → 사건 → 전달 시나리오 검사가 같은 결과를 낸다.
- **결정 필요:** D3.

### M5 — 계층 간 판단 (Windows 확장 2단계)

- **목표:** WSL 값과 호스트 값을 함께 보고 경보와 안내를 낸다.
- **범위:**
  - 호스트 가용 메모리·커밋 비율 경보. 호스트 미관측은 경보 유지, 정상 처리하지 않는다.
  - 드라이브별 기준 또는 절대 용량 하한(N5), CLI의 `C/D/E` 고정 문구 제거.
  - 드라이브 사건에 VHDX 비중·회수 가능량 근거를 붙이고, WSL 디스크 행에 호스트 드라이브 여유를 함께 표시한다(N4). 회수 절차는 문서로 안내하고 자동 실행하지 않는다.
  - Linux 측 보강: CPU·IO PSI, GPU 메모리.
  - 설정에서 뺀 드라이브의 사건이 `unknown`으로 계속 남는 동작(코드 확인)을 함께 정리한다.
- **완료 기준:** 새 조건별 지속·회복·미관측 회귀 검사, 설정 화면 브라우저 검사, 실제 호스트 값으로 판정 확인.
- **결정 필요:** D4.

### M6 — 이력·조회 비용

- **목표:** 7일/14일 조회와 컨트롤러의 상시 비용을 줄인다. 기준선은 리뷰 실측값이다(7일 이력 약 4초, 컨트롤러 평균 3.7% 코어·최고 메모리 약 193 MiB).
- **범위:** Guard가 날짜별 집계 파일을 쓰고 조회가 그 파일을 읽게 한다(S2). 적중하지 않는 프로세스 내 캐시를 제거한다. 전달 worker의 반복 파일 읽기와 `/proc` 스캔을 줄인다(S4). 컨트롤러 비용은 원인별 비중을 먼저 측정한 뒤 범위를 정한다.
- **완료 기준:** 같은 방법으로 다시 측정한 전후 수치, 집계 결과가 원본 이력 계산과 일치하는지 검사.

### M7 — Windows 동반 구성요소 (Windows 확장 3단계)

- **목표:** WSL 안에서는 할 수 없는 일을 Windows 측에서 맡는다.
- **범위:** Guard의 생존 표식을 확인해 VM 정지·무응답을 Windows 알림으로 알리는 감시(N6), 로그온 작업의 설치·제거 스크립트, 절전·재개와 WSL 재시작 기록. 현재 사용자 권한으로만 동작하고, WSL로 들어오는 명령은 기존의 제한된 연산만 쓴다.
- **완료 기준:** 격리된 배포판이나 테스트 유닛으로 정지 감지 확인, 설치·제거 왕복 확인, 실제 호스트 재부팅 확인 여부를 구분해 기록.
- **결정 필요:** D5.

### M8 — 전환 평가와 이름 변경

- **목표:** M7의 Go 구성요소 운영 결과와 M6의 측정값으로 소유자 worker·컨트롤러의 Go 전환 여부를 정한다. 저장소 이름을 `windows-wsl-resource-guard`로 바꾼다.
- **범위:** 전환을 택하면 M2의 형식 문서를 기준으로 소유자 worker부터 교체한다. 이름 변경은 저장소 이름·문서·패키지 메타데이터부터 하고, CLI `wrg`·설정·상태 경로·유닛 이름은 유지한다.
- **결정 필요:** D6.
