# 사용성 결함 수정 및 확장 검증 — 2026-10-09

기준: `60d391b`. [리뷰](2026-10-09-scenario-usability-review.md)의 U1–U7 수정, 작은 사용성 개선, 대규모 데이터·모바일 자동 검증을 수행한다. 설정은 한 건씩 적용한다. 운영 배포와 원격 push는 범위 밖이다. 실기기 확인은 자동화와 구분한다.

## 실행 기록

- 설정 요청의 연속/동시 덮어쓰기, 처리 결과 읽기 실패, 잘못된 요청 파일, Guard 중단·만료, ID별 조회와 오류 전파에 대한 8개 검사를 추가했다. 기존 코드에서 예상한 실패를 확인했다.
- Controller의 공유 작업 잠금 안에서 이전 결과 확인과 새 요청 저장을 묶었다. 처리되지 않은 요청은 409, 보관되지 않은 ID는 404, 처리 상태 읽기 오류는 503으로 전달한다. 기존 요청/결과 파일을 유지하고 ID·수집 주기·최근 Guard 관측 시각을 상태 API로 제공한다.
- 새 8개 검사와 기존 서비스 제어 74개·웹 29개·daemon 38개 검사 통과. 임시 소유자 디렉터리와 실제 Controller/daemon 함수를 사용했으며 운영 서비스 명령은 실행하지 않았다. UI 연결·전체 회귀·확장 검증은 이어서 수행한다.
- UI에 요청 ID 추적과 sessionStorage 복원을 연결했다. 서버 상태를 별도 조회해 화면 이동과 무관하게 확인하고, 이전/다른 요청 결과·조회 실패·404는 완료로 인정하지 않는다. Guard 수집 주기에 따른 대기/수동 확인 안내를 제공한다. 손상된 결과 JSON도 503으로 드러내는 검사를 추가했다.
- 조회를 섹션별로 적용하며 첫 실패·이전 데이터·마지막 성공 시각과 재시도를 표시한다. 읽기 30초/쓰기 130초 제한, 불필요한 이전 조회 취소, 같은 조회 공유, 요청별 중복 갱신 1회 예약을 연결했다. POST 결과 미확인은 자동 재전송하지 않고 명시적인 CSRF 거부만 1회 갱신/재시도한다.
- 대화상자와 로그 요청의 세대 번호를 대조해 이전 응답을 버린다. 등록 실패는 입력을 유지하고 버튼을 복구하며, 검색 중에도 중복 등록을 막는다. 설정 오류는 대화상자 안에 표시하고 aria 연결과 입력 초점을 유지한다. 비활성 서비스 버튼 설명과 일괄 종료의 전체 범위를 표시한다.
- Chromium·WebKit 각각 PC/모바일 상호작용 26개, 빈 데이터 30개 화면, Escape 3개와 모바일 회전/터치/제어된 visibility 이벤트 검사가 통과했다. 기존 Chromium offline suite도 통과했다. 모바일 오류 화면을 직접 확인했다. visibility 이벤트 검사는 실제 OS의 백그라운드 중단 검증이 아니다.
- 확장 검증에서 서비스 500개×288개 메모리 표본을 Math.max의 인수로 펼치다 `Maximum call stack size exceeded`가 발생했다. 같은 최대값을 순차 계산하도록 수정해 대규모 차트와 조작 검사를 통과했다. 대규모 렌더링의 시간 목표 초과는 별도 성능 제한으로 유지한다.
- 전체 단위 검사 439개 중 437개 통과, root credential 전용 2개 skip. JS 구문·actionlint·릴리스 관련 단위 5개 통과. fixture traceback과 기존 ResourceWarning은 실제 운영 오류나 추가 통과로 집계하지 않는다.
