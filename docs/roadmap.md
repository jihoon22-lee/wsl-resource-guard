# 예정 작업과 미해결 항목

아직 고치지 않은 결함, 구조 개선, 확장 계획을 한곳에 둡니다. 항목을 처리하면 이 문서에서 지우고 변경 내용은 [변경 기록](../CHANGELOG.md)에 적습니다. 과거 경과는 Git 이력에 있습니다.

## 미해결 결함

| ID | 중요도 | 내용 | 위치 | 수정 방향 |
|---|---|---|---|---|
| N1 | P2 | WSL을 다시 시작하면 지속 중인 디스크 경보가 새 사건으로 다시 열리고, 이전 사건은 30분 뒤 회복 알림을 보냅니다. 디스크는 계속 기준 미만입니다 | `incidents.py`의 `_key`, `reconcile` | 디스크 사건 키에서 boot ID를 빼고 저장된 구형 키를 이전 |
| N2 | P2 | Windows 토스트 경로(`/mnt/c` 조회·실행)가 멈추면 전달 worker가 멈춰 Gmail·푸시를 포함한 모든 알림이 중단됩니다 | `notifications.py`의 `_send_windows_toast` | 시간 제한이 있는 단일 실행 보조 작업으로 실행 |
| N3 | P3 | 전송 실패 원인이 전달 기록과 저널 어디에도 남지 않습니다 | `delivery.py`의 `tick` | 비밀값이 없는 짧은 원인을 보관·출력·표시 |
| N4 | P3 | VHDX가 호스트 드라이브를 채운 상황이 드라이브 경보의 원인으로 연결되지 않고, WSL 디스크 여유 표시가 호스트 드라이브 여유를 반영하지 않습니다 | `disks.py`의 `disk_insights`, `collect_disks` | 드라이브 사건에 VHDX 비중·회수 가능량을 붙이고 호스트 여유를 함께 표시 |
| N5 | P3 | 디스크 기준이 모든 드라이브 공통 백분율뿐입니다. CLI에는 `C/D/E` 문구가 고정돼 있습니다 | `config.py`, `disks.py`의 `disk_severity`, `cli.py`의 `cmd_disks` | 드라이브별 재정의와 선택적 절대 용량 하한 |
| N6 | P3 | Guard가 멈추거나 WSL VM이 내려가도 알림이 오지 않습니다 | `packaging/wsl-resource-guard.service` | 유닛 watchdog, VM 정지는 Windows 측 감시 |
| N7 | P3 | 주간 리포트는 지정 요일에 PC가 꺼져 있으면 그 주를 건너뜁니다 | `daemon.py`의 `weekly_report_slot` | 같은 ISO 주 안에서 놓친 발송을 따라잡기 |
| N8 | P3 | 설정에서 뺀 드라이브의 사건이 `unknown` 상태로 계속 남습니다 | `incidents.py`의 `reconcile` | N5와 함께 정리 |

N1과 N2는 재현으로 확인했습니다. N1은 boot ID만 바꾼 `evaluate → reconcile → Delivery.tick` 흐름에서, N2는 PowerShell 경로 조회를 멈춘 상태의 `Delivery.tick`에서 확인했습니다. N8은 코드로만 확인했습니다.

## 구조·효율 개선

| ID | 내용 |
|---|---|
| S1 | `daemon.sample()` 한 함수에 수집·평가·경보 유지·구형 알림·저장이 섞여 있고, 회복 판정이 `sample`과 `reconcile` 두 곳에 있습니다. 데몬은 구형 알림 경로(`notify=True`)를 쓰지 않습니다 |
| S2 | 이력 한 줄이 약 6 KB이고 7일·14일 조회마다 전체를 다시 파싱합니다. 소유자 worker가 호출마다 새 프로세스라 프로세스 내 캐시는 적중하지 않습니다. Guard가 날짜별 집계 파일을 쓰는 방식으로 바꿉니다 |
| S3 | 원자적 저장 구현이 5곳에 따로 있고 fsync 여부가 다릅니다. `webpush.send_all`의 만료 목록 저장은 원자적이지 않습니다 |
| S4 | 전달 worker가 2초마다 여러 파일을 읽고, `/proc` 스캔이 다른 사용자 프로세스까지 읽은 뒤 UID로 거릅니다 |
| S5 | PowerShell 경로가 3곳에 고정돼 있고 doctor의 `.wslconfig` 탐색은 Windows 사용자 폴더 목록의 첫 항목을 씁니다. `SystemMetrics`가 평면 필드라 필드를 늘린 뒤 이전 버전으로 되돌리면 직전 상태를 잃습니다 |

## 마일스톤

마일스톤 하나가 작업 브랜치 하나입니다. 릴리스·원격 push·운영 배포는 요청이 있을 때 합니다.

| 순서 | 이름 | 다루는 항목 | 선행 |
|---|---|---|---|
| M1 | 알림 신뢰성 | N1, N2, N3 | 없음 |
| M2 | 기반 정리 | S3, N6(유닛 watchdog), N7, 저장 형식 문서화 | M1 |
| M3 | 호스트 관측 | Windows 호출 전담 모듈, 호스트 스냅샷, 화면 표시, S5 | M2 |
| M4 | 판정 구조 정리 | S1 | M2 |
| M5 | 계층 간 판단 | 호스트 메모리 경보, N4, N5, N8, CPU·IO PSI, GPU 메모리 | M3, M4 |
| M6 | 이력·조회 비용 | S2, S4, 컨트롤러 비용 | M2 (병행 가능) |
| M7 | Windows 동반 구성요소 | VM 정지 감시(N6), 로그온 작업 설치 스크립트, 절전·재개 기록 | M3 |
| M8 | 전환 평가와 이름 변경 | 소유자 worker·컨트롤러의 Go 전환 평가, `windows-wsl-resource-guard` | M6, M7 |

M4를 M5 앞에 두는 이유는 호스트 조건을 추가할 때 PSI·디스크에 이은 세 번째 개별 유지 분기를 만들지 않기 위해서입니다.

### M1에서 정한 것

- N1: 디스크 사건 키를 `disk.E::<boot_id>`에서 `disk.E::host`로 바꿉니다. 저장된 구형 키는 `reconcile()` 시작 시 이전합니다. 현재 부팅의 행은 키만 바꾸고, 다른 부팅의 해소 행은 회복 대기 표시를 지웁니다. 다른 부팅의 미해소 행은 같은 드라이브의 미해소 행이 있으면 알림 없이 대체 처리하고, 없으면 같은 사건으로 이어 갑니다. RAM·PSI·swap·OOM·MCP·세션 사건은 부팅 범위를 유지합니다.
- N2: 토스트 전송을 기존 `bounded_probe`로 감쌉니다. 제한은 내부 PowerShell 제한(15초)보다 긴 20초입니다. 응답이 없으면 접수 여부 미확인으로 기록하고 자동 재전송하지 않습니다.
- N3: 전달 기록의 수신처 항목에 `reason`(200자 이내, 예외는 종류 이름만)을 남기고 저널에 한 줄 출력하며 경보 상세 화면에 표시합니다.

### M3 — 호스트 관측

설치 없이 WSL 안에서 interop으로 조회합니다. 경보에는 연결하지 않고 화면 표시까지만 합니다.

- Windows 호출은 모듈 하나가 맡습니다. 실행 파일 위치 확인, 시간 제한, 단일 실행, 연속 실패 시 간격 확대, 출력 크기 제한, 고정 스크립트만 실행합니다. 토스트와 현재의 vmmem 조회, doctor의 `.wslconfig` 탐색을 여기로 옮깁니다.
- 수집은 소유자 Guard에서만 합니다. root 컨트롤러는 Windows 실행 파일을 호출하지 않습니다.
- 스냅샷은 `metrics.host` 아래의 버전 있는 구조로 두고, 관측 시각·시도 시각·상태를 값과 함께 저장합니다. 이력은 낮은 주기의 별도 파일에 씁니다.

조회 가능한 항목과 한 번씩 잰 소요 시간입니다. PowerShell 기동만 0.32초이고, 한 스크립트로 묶으면 기동은 한 번입니다.

| 항목 | 방법 | 소요 |
|---|---|---|
| 호스트 물리 메모리 전체·여유 | `Win32_OperatingSystem` | 0.69초 |
| 커밋 사용량·한도, 대기 캐시 | `Win32_PerfFormattedData_PerfOS_Memory` | 0.82초 |
| 페이지 파일 | `Win32_PageFileUsage` | 0.57초 |
| vmmem 작업 집합 (현행) | `Get-Process vmmem*` | 0.52초 |
| 고정 볼륨 전체 (WSL에 마운트되지 않은 것 포함) | `[IO.DriveInfo]::GetDrives()` | 0.43초 |
| 메모리 상위 Windows 프로세스 | `Get-Process` 정렬 | 0.53초 |
| 배포판 목록·상태 | `wsl.exe -l -v` | 0.09초 |
| 배포판별 VHDX 위치 | `HKCU`의 `Lxss` 레지스트리 | 0.43초 |
| CPU·IO 압력, GPU 메모리 | `/proc/pressure/cpu`·`io`, `nvidia-smi` (Linux 측) | — |

`Get-Counter`는 3초가 걸려 쓰지 않습니다.

### M7·M8 — 구현 언어

전면 재작성은 하지 않습니다. 수집 안정성 문제는 설계에서 나왔고, 호스트 수집 비용은 PowerShell 기동이라 호출하는 쪽 언어와 무관합니다. 컴파일 언어는 두 곳에만 순서대로 검토합니다.

1. Windows 동반 구성요소(M7)는 Go 단일 실행 파일을 검토합니다. Windows에 런타임을 설치하지 않아도 됩니다. 서명 없는 실행 파일에 대한 Windows 보안 기능의 반응은 먼저 확인해야 합니다.
2. 소유자 worker와 컨트롤러(M8)는 M7의 운영 결과와 M6의 측정값을 보고 정합니다. 운영 실측에서 컨트롤러 cgroup은 평균 3.7% 코어(Guard는 0.48%)를 썼고 최고 메모리가 유닛의 `MemoryHigh=192M`에 도달했습니다. 원인별 비중은 M6에서 측정합니다.

구성요소를 하나씩 바꾸려면 M2의 저장 형식 문서가 먼저 있어야 합니다.
